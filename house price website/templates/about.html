🎯 Project Overview

EstateAI is a machine learning web application that estimates residential real estate prices across 19 prime Delhi-NCR localities. It compares three distinct regression algorithms (Random Forest, Linear Regression, and Decision Tree) and features an interactive geospatial map capable of distinguishing between operational territory and unsupported cities in real-time.

🧹 Data Pipeline & Cleaning Methodology

The training data originated from the Kaggle Delhi-NCR Real Estate Dataset (scraped from MagicBricks). Raw web-scraped data contains missing values, advertising descriptions in locality fields, and unrealistic outliers. Our cleaning script (clean_kaggle_data.py):

  • Extracted and standardized 19 recognized prominent localities.
  • Imputed missing bathroom values based on bedroom (BHK) counts.
  • Filtered extreme outliers (retaining properties between 350 sq ft and 7,000 sq ft, priced between ₹15 Lakhs and ₹12 Crores).
  • Produced a clean, model-ready dataset (cleaned_kaggle_housing.csv) with 742 verified listings.

scikit-learn

Core machine learning library used for One-Hot Encoding, Linear Regression, and Random Forest bagging.

Geospatial map visualization with CartoDB Voyager tiles and operational boundary buffers.

Free, zero-key reverse geocoding to resolve clicked coordinates into city/district names.

Seaborn & Matplotlib

Statistical data visualization generating correlation and model evaluation heatmaps.

🎓 Common Viva & Interview Questions

Q1: Why does Random Forest perform better than Linear Regression on this dataset?
Real estate prices do not scale in a purely linear manner; luxury sectors and larger configurations have non-linear price spikes. Random Forest aggregates 100 decision trees trained on random subsets of data and features, capturing these non-linearities while preventing single-tree overfitting, yielding an R² score of 80.8% compared to 79.3% for Linear Regression.
Q2: How does the map detect if a clicked location is invalid?
The map combines two checks: first, a client-side Haversine distance check to measure proximity to the 19 supported operating hubs (threshold: 5.0 km). Second, if outside, it queries the free OpenStreetMap Nominatim reverse geocoding API to resolve the exact city name (e.g. Gurugram, Ghaziabad, Jaipur) and displays a clear "Service Unavailable" alert.
Q3: How are categorical location strings handled by the ML model?
Machine learning models require numerical matrices. We use OneHotEncoder(handle_unknown='ignore') wrapped inside a ColumnTransformer pipeline. This converts each locality into binary indicator features (0 or 1) without imposing an artificial ordinal hierarchy.
